# 敏感文件防火墙安全模型

## 任务与范围

Guard 是本地访问防火墙，不是杀毒软件、EDR 或网络 DLP。目标是在受保护浏览器认证数据和 SSH 私钥被成功打开前，阻止未经授权的本地进程读取。

自动化测试只使用合成浏览器 profile、临时 SSH key 和临时目录。日志只允许记录路径类别、进程元数据、决策和错误代码，禁止记录 Cookie、密码、session token、数据库行或私钥字节。

## 共同授权规则

1. 未命中受保护资源时立即允许，不要求无关进程字段完整。
2. 命中资源后必须验证 PID、启动时间、规范化可执行路径、设备号、inode 和用户身份；进程名不能单独建立信任。
3. 确定性策略直接返回。只有浏览器迁移和 SSH 读取可以进入人工确认，而且必须受内核 deadline、队列容量、进程退出和身份变化限制。
4. 任何信息缺失、超时、响应失败、队列溢出或身份变化都默认拒绝。
5. 同一 UID 不等于可信。控制面必须验证签名身份、证书锚点、Team ID（正式包）和允许的标识符。

## 资源分类

- 浏览器资源按已验证的可执行文件、签名和 profile 所有者分类。
- 文件身份使用设备号和 inode，覆盖硬链接别名和替换后的资源。
- 目录树、SQLite 的 WAL/SHM sidecar、规范化路径和符号链接都在资源索引中处理。
- macOS Safari 使用独立的窄路径分类；其他浏览器沿用共享分类逻辑。
- 无法可靠分类时，只在已经命中受保护范围的情况下拒绝，避免把整台系统误纳入保护。

## 进程与控制面

Guard 不信任进程名、路径 basename、UID 或可伪造的环境变量。进程身份必须绑定 PID、启动时间、可执行文件路径和文件身份，PID 重用或父进程链断裂时拒绝。

Guard、`guardctl`、`guard-notify` 和 `guard-es` 的 IPC 客户端/服务端必须通过系统签名要求。macOS 自用包使用固定本地证书锚点加允许标识符；禁止退化为“同 UID 即允许”。

## Endpoint Security 与 fanotify

macOS 使用 Endpoint Security `AUTH_OPEN`，根据真实打开标志区分读、写和迁移读取；自用包保留 host 的系统扩展安装 entitlement 和 extension 的 Endpoint Security entitlement。只有同时具备生命周期状态、`guard-es` 运行、客户端建立、XPC 健康和策略健康，GUI 才能显示 Active。

Linux 使用 root `guardd` 和 fanotify permission events，需要 `CAP_SYS_ADMIN` 等能力。fanotify 无法在所有场景提供打开者原始标志，因此 Linux 不能宣称迁移读取始终只读。

## 明确不保护

- 已经打开的文件描述符和继承来的描述符不会被追溯关闭。
- 恶意浏览器扩展、浏览器内部（renderer/JIT）RCE、root/内核入侵和 Guard 启动前已经泄露的秘密不在保护范围内。
- Process Shield 不负责：将已信任浏览器标记为受控之前的、源自浏览器内部的代码执行；DevTools/远程调试滥用（除非后续独立阶段显式覆盖）；通用恶意软件分类。
- SSH agent 已经授予的签名能力不等同于文件读取，不由本模型回溯撤销。
- Guard 不修改 SIP、TCC、Secure Boot 或系统隐私数据库。

## 进程完整性（Process Shield）

受保护资源打开前，除已验证的进程身份外，还要求该确切存活进程实例未被确认妥协：

- 同一用户的非特权本地进程试图对受保护权威进程（已信任浏览器、Guard 组件、迁移/SSH 租赁根进程）执行外部进程控制/读取/注入（task control/read、trace、远程线程、DYLD 代码加载注入、代码签名失效后的利用），自 MPS 系列起进入保护范围。
- 状态模型是确定性的：`Normal` 或 `Compromised`。同一稳定实例只能从 `Normal` 变为 `Compromised`，不可逆转；进程退出销毁存活状态，PID 重用不会继承妥协状态。
- 已确认妥协的实例在浏览器/SSH 策略评估之前即失败关闭，拒绝原因为 `process_integrity_compromised`。被拒绝的攻击尝试本身不会把目标标记为妥协。
- 任务端口访问不弹人工确认框；未明确定义的未知/未信任请求者直接拒绝。
- 通知型信号（remote-thread、code-signing invalidation）只能宣称 DETECTED + CONTAINED，不能宣称 PREVENTED。

## 失败安全与可用性

Endpoint Security 或 fanotify 客户端退出后，内核事件通道会关闭；服务必须记录健康状态并由系统服务重启。缺少配置、空配置、错误所有者或坏权限时，不得显示“已保护”。

人工确认的有效期限是产品上限与平台消息 deadline 减安全余量的较小值。余量不足时拒绝并审计，不发送迟到响应，也不保留过期请求。

## 部署建议

- Linux：普通用户编译，安装时才使用 `sudo deploy/install.sh`；配置由 `guardctl setup` 明确生成，已有配置不覆盖。
- macOS：先在 SIP 开启状态完成签名和离线安全门，再由用户从 Recovery 手动关闭 SIP；随后启用开发模式、安装扩展并在系统设置批准完全磁盘访问。
- `LOCAL_SIGNING_ONLY=1` 只能做无 entitlement 的打包 smoke test；真实 macOS 自用保护必须使用 `SELF_USE_SIP_OFF=1` 和本地证书。
