# 平台架构

## 分层

1. `guard-core`：跨平台策略、资源索引、进程身份、授权队列、审计模型。
2. `guard-platform`：定义文件身份、进程查询、授权事件和系统服务边界。
3. `platform-linux`：root `guardd`、fanotify、systemd、polkit。
4. `platform-macos`：Endpoint Security、System Extension、签名身份、XPC 和系统权限状态。
5. GUI/CLI/通知：只调用平台服务接口，不直接操作内核事件。

## 事件流程

内核事件先经过资源范围筛选，再做文件身份和进程身份验证。确定性策略立即返回；只有迁移或 SSH 读取的明确确认可以保留不透明操作，但必须受 deadline、队列容量、进程退出和身份变化约束，任何异常都拒绝。

## 平台差异

- Linux fanotify 只提供本平台允许的打开权限信息，不能宣称所有迁移读取都是只读。
- macOS Endpoint Security 根据 `AUTH_OPEN` 标志执行读写判断，并提供更精确的读取控制。
- 两个平台都不追溯已经打开的文件描述符、不解决 root/内核入侵、不修改 TCC 或系统安全设置。

## IPC 和身份

控制面不信任进程名、UID 或 Unix 路径。正式签名使用 Team ID 与标识符；macOS 自用签名使用固定本地证书锚点与允许的标识符。`Guard`、`guardctl`、`guard-notify` 和 `guard-es` 的身份范围严格限定。

## 配置和测试

配置由用户明确生成并原子写入。启动时拒绝空配置、错误所有者和不一致 profile。测试必须使用合成浏览器和临时 SSH key；平台特有的 root、SIP 和 entitlement 验收单独记录。
